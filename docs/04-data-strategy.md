# 혜택 데이터 전략

국내 카드사는 혜택 API를 제공하지 않는다. 그래서 혜택 데이터를 직접 만들고 검수하는 것이 이 앱의 가장 큰 일이다.

## 데이터 출처 (신뢰도 순)

| 출처 | 용도 |
| --- | --- |
| 카드사 상품설명서 PDF·상품 페이지 | 1차 원천. 여신금융협회 심의를 거친 공식 문서 |
| 여신금융협회 신용카드 상품 공시 | 전체 상품 목록, 신규·변경 감지 (구조화 수준은 확인 필요) |
| 사용자 제보 (청구서 대조 “달라요”) | 오류 보정 |
| 타사 DB (카드고릴라 등) | 복제 금지. 우선순위 참고만 |

카드 부가서비스는 출시 후 3년 이상 축소·폐지가 제한된다(경영 위기 등 예외 제외). 한 번 검수하면 변경 빈도가 낮다.

## 수집 → AI 추출 → 검수 → 게시 (확정 흐름)

1. **수집**: 카드명 입력 시 상품 페이지·PDF 자동 수집. 실패하면 관리자가 링크나 파일 업로드. 사이트 이용약관·robots.txt 확인.
2. **AI 추출**: 정해진 스키마로 혜택 추출(할인율, 한도, 실적 구간, 건당·월 횟수, 최소금액, 제외 조건, 간편결제 조건 등). **항목마다 근거 문장과 페이지 번호를 붙인다.**
3. **검수**: 웹 관리자 화면에서 원문과 추출 결과를 나란히 본다. 항목을 누르면 원문 근거가 하이라이트된다. 규칙 검증(할인율 100% 초과, 구간 누락, 한도 역전 등)에 걸린 항목을 경고로 먼저 보여준다.
4. **게시**: 확인하면 앱에 반영. 검수 전 데이터는 추천에 쓰지 않고 “계산 불가”로 표시.
5. **버전 관리·변경 감지**: 혜택마다 유효기간, 출처 문서, 페이지 기록. 문서 해시 비교로 바뀐 카드만 재처리(월 1회 정도).
6. **배포**: 앱은 변경분만 받아 기기에 저장, 추천 계산은 기기 안에서.

MVP 검수자는 기획자 본인. 목표 카드당 15~30분(실측 전 추정). **처음 5장은 AI 없이 직접 상품설명서를 읽고 구조화**해서 스키마를 검증한다.

## 커버리지

- 최종 목표: 신용·체크 인기 상위 300장 + 요청 많은 단종 카드
- 1단계 20장: 유형별 대표 카드(신용 10·체크 10). 혜택 구조 유형을 각 2장 이상 포함: 전월실적 구간형, 통합 할인한도형, 무실적형, 선택형, 포인트·마일리지형, 간편결제 조건형, 체크카드 캐시백형
- 기획자 본인 카드는 C안(요청 → 검수 → 게시)으로 추가해 두 경로를 모두 테스트
- 목록에 없는 카드: 요청 대기열, 요청 수 순으로 처리

## 가맹점 ↔ 업종 매핑 (별도 DB)

- 브랜드 사전: 주요 브랜드 수백 개를 혜택 대상 업종과 매핑 (대부분 혜택이 브랜드 단위)
- 지도 API 카테고리 → 우리 업종 분류 매핑 테이블
- 사용자 제보로 오분류 보정

## 전월 실적 처리 (확정)

국내 카드 대부분은 지난달 사용액으로 이번 달 혜택이 정해져 추천 결과를 크게 바꾼다.

- 카드 등록 시 구간만 선택 (카드의 실적 조건에 맞춘 구간 + “잘 모르겠어요”)
- 모르면 “실적 충족 시 / 미달 시” 혜택을 함께 표시
- 매월 1일, 기록으로 추정한 구간을 카드별로 원탭 확인·수정 (기록 누락, 실적 제외 항목 때문에 추정이 틀릴 수 있음)
- 무실적 카드는 입력 불필요

## 정확도 측정 (확정)

- 결제 기록을 다음 달 청구서와 건별로 “맞아요 / 달라요” 대조
- 일치율 = MVP 성공 기준(목표 90%)
- “달라요”는 실제 금액·사유와 함께 관리자 검수 대기열로 신고, 데이터 수정 시 알림
