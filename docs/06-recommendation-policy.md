# 추천 계산 정책 (2단계)

2026-11-08 기획자와 논의한 내용. “확정”은 구현 기준, “제안”은 기획자 확인 대기.

## 1. 비교 단위 — 확정

- 모든 혜택을 원화로 환산해 비교한다.
- 포인트: 현금처럼 쓸 수 있으면 1P = 1원.
- 마일리지: 1마일 = 15원(기본값), 사용자가 설정에서 변경 가능. 선택지: 보수적 10원 / 기본 15원 / 적극적 20원 / 직접 입력.
  - 적립률(예: 1,000원당 1마일)은 카드 데이터 값이고, 마일 가치(1마일 = 15원)는 환산 기준이다. 둘을 곱해 원화로 비교한다. 예: 6,000원 결제, 1,000원당 1마일 → 6마일 × 15원 = 90원 상당(1.5%).
  - 결과 아래 문구: “대한항공 마일리지는 1마일 = 15원으로 계산했어요. 항공권에 쓰면 가치가 더 높고, 쇼핑에 쓰면 낮아질 수 있어요. [바꾸기]”

## 2. 금액 미입력 시 — 확정

- 정률(%)과 정액(원), 최소 결제금액 조건 때문에 금액에 따라 순위가 바뀐다.
- 금액이 없으면 업종별 대표 금액(예: 카페 6,000원, 편의점 5,000원)으로 계산한 **예상 결과**로 순위를 매기고 “6,000원 기준”을 표시한다.
- 금액 입력 칸 옆에 빠른 선택 버튼(5천 / 1만 / 3만)을 둔다.
- 업종별 대표 금액 표는 3단계 데이터 기획에서 정한다.

## 3. 한도 — 확정

- 남은 한도까지만 부분 적용한다. 예: 6,000원 × 20% = 1,200원이지만 남은 한도가 500원이면 500원.
- 계산 근거에 “한도 500원 남음으로 일부만 적용”을 표시한다.
- **등록 시점의 한도 문제 — 확정 (아래 네 가지 모두 적용)**
  1. 등록 시점부터 사용액 0으로 시작, 등록한 달에는 “등록 전 사용분은 반영되지 않았어요” 표시
  2. 등록 화면에서 “이번 달 이미 받은 혜택”을 선택 입력으로 받기
  3. 카드 혜택 상세에서 혜택별 사용액을 직접 수정 가능
  4. 다음 달부터 기록·청구서 대조로 보정

## 4. 동률 처리 — 확정

- 기본 추천 우선순위: ① 실적이 부족한 카드(실적 채우기) → ② 한도가 넉넉한 카드 → ③ 체크카드(소득공제율 유리)
- 기본 추천에 이유를 한 줄로 보여주고, 다른 선택지를 이유와 함께 옵션으로 함께 보여준다.
  - 예: “두 카드 혜택이 같아요 · 신한카드를 추천해요: 이번 달 실적 5만원이 부족해요” / 다른 선택: [한도 여유] ○○ · [소득공제 유리] ○○
- 동률 범위: 혜택 차이 100원 이내면 동률로 본다.

## 5. 혜택 합산 — 확정

- 기본 적립과 추가 적립(특별 적립 등)이 함께 있으면 합산한다.
- 같은 카드 안에서 중복이 안 되는 혜택은 카드 데이터의 규칙을 따른다 (3단계 스키마에서 표현).

## 6. 추천 모드 — 확정

- MVP는 “이번 결제 최대 혜택”만 제공한다.
- 실적이 부족한 카드에는 “이 카드 실적 5만원 남음” 같은 안내만 붙인다. “이번 달 최대” 모드는 v2.

## 7. 가맹점 전용 적립 카드 — 확정

예: 쿠팡 제휴카드처럼 특정 가맹점에서 혜택이 큰 카드. 계산은 일반 규칙과 같고, 아래를 추가로 정한다.

1. **가맹점 전용 포인트 가치**: 특정 가맹점에서만 쓰는 포인트(예: 쿠팡캐시)는 기본 1P = 1원. 결과에 “쿠팡에서만 사용 가능”을 표시하고, 마일리지처럼 사용자가 가치를 바꿀 수 있다.
2. **온라인 가맹점 MVP 포함**: 위치로 잡히지 않는 쿠팡·쿠팡이츠·배달앱 등은 장소 선택 화면의 검색과 업종 버튼(온라인 쇼핑, 배달앱)으로 MVP에 포함한다. 별도 온라인 기능(브라우저 확장, 결제 직전 자동 알림)은 이후.
3. **사용자 조건**: 멤버십 가입 같은 카드 밖 조건이 있는 카드는 등록 시 질문 하나로 받는다(예: “쿠팡 와우 회원인가요?”). 카드 상세에서 변경 가능. 실제 조건은 3단계에서 상품설명서로 확인한다.
4. **가맹점별 카드 고정**: v2. 고정해도 계산은 계속 돌리고, 다른 카드가 더 유리하면 “이번엔 ○○카드가 500원 더 이득”만 알린다.

## 8. 할인·적립 표시 — 확정

순위는 원화 환산액 하나로 매기고, 표시는 혜택 종류를 그대로 보여준다. 현금이 아닌 혜택에는 “상당”을 붙인다.

| 종류 | 큰 숫자 | 보조 설명 |
| --- | --- | --- |
| 할인 | 1,200원 할인 | 청구 시 할인 / 결제일 할인 |
| 캐시백 | 600원 캐시백 | 다음 달 지급 |
| 포인트 | 90원 상당 | 90P 적립 |
| 마일리지 | 90원 상당 | 6마일 적립 · 1마일 = 15원 [바꾸기] |
| 가맹점 전용 포인트 | 120원 상당 | 쿠팡캐시 · 쿠팡에서만 사용 |

- 지급 시점(즉시 / 청구 시 / 다음 달)을 함께 표시한다.
- 한 카드에서 할인과 적립이 같이 나오면 합계를 크게, 내역을 아래에 표시한다. 예: “1,290원 상당 = 1,200원 할인 + 6마일”.
- 현금성 혜택 선호 설정은 v2.

## 9. 간편결제 경유 계산 — 확정

같은 매장이라도 결제수단에 따라 혜택이 포함·제외·추가될 수 있다.

1. **기본 결제수단 설정**: 처음에 주 결제수단을 받는다(실물·터치 결제 / 네이버페이 / 카카오페이 / 토스페이 등). 기본값은 실물·터치 결제. 애플페이는 국내 지원 카드사가 제한적이라 카드별로 데이터에 표시한다.
2. **결과 화면 결제수단 칩**: 바꾸면 즉시 재계산한다.
3. **경고·팁**: “네이버페이로 내면 이 카드 혜택이 없어요” / “이 카드는 네이버페이로 내면 500원 더 받아요”.
4. **온라인 가맹점 기본 결제 경로**: 브랜드 사전에 “기본 결제 경로” 칸을 추가해, 결제 경로가 정해진 가맹점(쿠팡, 배민 등)은 그 경로로 자동 계산한다. 값은 3단계에서 채운다.
5. **결제 기록에 결제수단 포함**: 청구서 대조 정확도를 위해 기록 화면에 결제수단을 남긴다.

3단계 스키마 반영 사항: 혜택마다 “간편결제 포함 / 제외 / 전용”과 대상 페이 목록, 카드별 애플페이 지원 여부.

## 남은 논의

추천 계산 정책의 논의 항목은 모두 정리됐다. 실적·한도 정책(월 기준일, 취소·환불, 실적 제외 항목)과 예외 처리 정책은 별도 문서에서 다룬다.
