# 추천 계산 정책 (2단계, 작성 중)

2026-11-08 기획자와 논의한 내용. “확정”은 구현 기준, “제안”은 기획자 확인 대기.

## 1. 비교 단위 — 확정

- 모든 혜택을 원화로 환산해 비교한다.
- 포인트: 현금처럼 쓸 수 있으면 1P = 1원.
- 마일리지: 1마일 = 기본값 원, 사용자가 설정에서 변경 가능.
  - **기본값 15원 — 제안 (확인 대기)**. 선택지: 보수적 10원 / 기본 15원 / 적극적 20원 / 직접 입력.
  - 결과 아래 문구: “대한항공 마일리지는 1마일 = 15원으로 계산했어요. 항공권에 쓰면 가치가 더 높고, 쇼핑에 쓰면 낮아질 수 있어요. [바꾸기]”

## 2. 금액 미입력 시 — 제안 (설명 후 확인 대기)

- 정률(%)과 정액(원), 최소 결제금액 조건 때문에 금액에 따라 순위가 바뀐다.
- 금액이 없으면 업종별 대표 금액(예: 카페 6,000원, 편의점 5,000원)으로 순위를 매기고 “6,000원 기준”을 표시한다.
- 금액 입력 칸 옆에 빠른 선택 버튼(5천 / 1만 / 3만)을 둔다.
- 업종별 대표 금액 표는 3단계 데이터 기획에서 정한다.

## 3. 한도 — 확정

- 남은 한도까지만 부분 적용한다. 예: 6,000원 × 20% = 1,200원이지만 남은 한도가 500원이면 500원.
- 계산 근거에 “한도 500원 남음으로 일부만 적용”을 표시한다.
- **등록 시점의 한도 문제 — 제안 (확인 대기)**
  1. 등록 시점부터 사용액 0으로 시작, 등록한 달에는 “등록 전 사용분은 반영되지 않았어요” 표시
  2. 등록 화면에서 “이번 달 이미 받은 혜택”을 선택 입력으로 받기
  3. 카드 혜택 상세에서 혜택별 사용액을 직접 수정 가능
  4. 다음 달부터 기록·청구서 대조로 보정

## 4. 동률 처리 — 확정 (범위만 제안)

- 기본 추천 우선순위: ① 실적이 부족한 카드(실적 채우기) → ② 한도가 넉넉한 카드 → ③ 체크카드(소득공제율 유리)
- 기본 추천에 이유를 한 줄로 보여주고, 다른 선택지를 이유와 함께 옵션으로 함께 보여준다.
  - 예: “두 카드 혜택이 같아요 · 신한카드를 추천해요: 이번 달 실적 5만원이 부족해요” / 다른 선택: [한도 여유] ○○ · [소득공제 유리] ○○
- **동률 범위: 차이 100원 이내 — 제안 (확인 대기)**

## 5. 혜택 합산 — 확정

- 기본 적립과 추가 적립(특별 적립 등)이 함께 있으면 합산한다.
- 같은 카드 안에서 중복이 안 되는 혜택은 카드 데이터의 규칙을 따른다 (3단계 스키마에서 표현).

## 6. 추천 모드 — 확정

- MVP는 “이번 결제 최대 혜택”만 제공한다.
- 실적이 부족한 카드에는 “이 카드 실적 5만원 남음” 같은 안내만 붙인다. “이번 달 최대” 모드는 v2.

## 남은 논의

- 특정 가맹점 전용 적립 카드(예: 쿠팡 제휴카드) 처리 방식
- 할인과 적립이 섞였을 때 표시 방식(“1,200원 할인” vs “1,200원 상당 적립”)
- 간편결제 경유 시 계산 (실물카드 결제와 결과를 나란히 보여줄지)
