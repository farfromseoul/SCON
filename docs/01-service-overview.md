## 서비스 컨셉

한국 카드의 복잡한 조건(전월실적, 통합한도, 선택형 혜택)까지 정확히 계산해서, 결제 직전에 “이 카드”를 알려주는 앱이다.

세 앱의 장점을 가져온다.

| 출처 | 가져올 장점 | 우리 방식 |
| --- | --- | --- |
| 카드피커 | 국내 카드, 카드사→상품 선택 등록, 업종·금액별 순위 비교, 원탭 결제 기록 | AI 추정 대신 검수된 데이터와 규칙 엔진으로 계산 |
| CardPointers | 위치 자동 감지, 잠금화면·위젯·Siri 등 앱 밖 진입점, 위치의 기기 내 처리 | iOS 네이티브 기능을 그대로 활용 |
| MaxRewards | 실제 사용 내역 기반 자동 추적 | 마이데이터 대신 원탭 기록·단축어 자동화로 대체 |

## 문제 정의

카드를 여러 장 가진 사람도 결제 순간에 어떤 카드가 가장 이득인지 알기 어렵다.

- **혜택 조건이 복잡하다**: 전월실적 구간, 통합 할인한도, 건당·월 횟수, 최소 결제금액, 간편결제 경유 시 제외 같은 조건이 겹친다.
- **내 상태에 따라 답이 달라진다**: 이번 달 실적과 남은 한도를 모르면 순위가 틀린다.
- **혜택 구조가 계속 변한다**: 매달 혜택 모드를 고르는 선택형 카드가 늘었다.
- **기존 앱은 추정에 의존한다**: 혜택을 AI로 추정하거나, 체크카드는 “정보 미제공”으로 나오는 경우가 있다.

메인 타깃은 신용·체크카드를 2장 이상 쓰는 사람이고, MVP 단계의 첫 사용자는 기획자 본인이다.

| 유형 | 특징 | 원하는 것 |
| --- | --- | --- |
| 일반 다카드 보유자 (메인) | 2\~3장, 혜택을 잘 모름 | “지금 뭐 쓰면 돼?” 한 줄 답 |
| 체크카드 중심 | 사회초년생, 대학생, 체크 선호자 | 체크카드도 정확한 계산, 연말정산 관점 |
| 혜택 관리형 | 4장 이상, 실적 구간 관리 | 실적·한도 추적, 정확한 계산 근거 |
| 관리자 | 기획자 본인 | 카드 데이터 조회·검수·게시 |

10년 전 같은 컨셉의 ‘추카’가 있었지만 지금은 찾기 어렵다. 데이터 유지 비용과 수익모델이 지속 여부를 가른다는 교훈이다.

## 차별점

우리 앱의 차별점은 “검수된 데이터로 정확하게, 앱을 열지 않고도 빠르게”다.

1. **정확도**: 사람이 검수한 데이터만 추천에 쓰고, 계산 근거와 불가 사유를 항상 보여준다.
2. **체크카드 완성도**: 신용·체크를 동등하게 지원하고, 체크카드 계산 정확도를 강점으로 내세운다. 연말정산 공제율까지 고려한 신용 vs 체크 선택도 제안한다.
3. **한국형 조건 반영**: 전월실적 구간, 통합한도, 선택형 카드의 이번 달 모드까지 계산한다.
4. **앱 밖 진입점**: 잠금화면 위젯, Live Activity, 단축어로 계산대 앞에서 바로 확인한다 (TestFlight 2차부터).

## MVP 범위와 단계별 확대

MVP는 유형별 대표 카드 20장 + 내 카드로 시작해, 검수 속도를 실측한 뒤 300장까지 늘린다.

1. **1단계 · 본인 사용** — 유형별 대표 카드 20장(신용 10 · 체크 10) + 내 카드(C안으로 추가). 처음 5장은 직접 구조화, 15장은 AI 추출 + 검수.
   - 넘어가는 조건: 스키마로 20장이 모두 표현되고, 내 카드 계산이 실제 청구서와 맞음
2. **2단계 · TestFlight (지인)** — 50장
   - 넘어가는 조건: 카드당 검수 시간을 실측해 300장 일정 산정
3. **3단계 · 출시 준비** — 100장 → 300장, 요청 많은 단종 카드 추가

20장에는 다음 혜택 구조를 각각 2장 이상 포함한다: 전월실적 구간형, 통합 할인한도형, 무실적형, 선택형, 포인트·마일리지형, 간편결제 조건형, 체크카드 캐시백형. 구체적인 20장 선정은 3단계(데이터 기획)에서 한다.

1단계에 포함하는 기능과 다음으로 미루는 기능:

| 카드별 혜택 조회 | 단축어 결제 문자 자동 기록 | 월간 리포트·놓친 혜택 |

## MVP 검증 가설과 성공 기준

MVP가 검증할 최우선 가설은 정확성이다: “추천한 혜택이 실제 청구서와 맞는가.”

| 가설 | 우선순위 | 성공 기준 (초안) |
| --- | --- | --- |
| 정확성 | 1 | 추천 결과와 실제 청구 할인 내역 일치율 90% 이상 |
| 속도 | 2 | 앱을 열고 추천을 확인하기까지 10초 이내 |
| 습관 | 3 | 실사용 기간 결제의 절반 이상에서 앱을 열어봄 |

측정 방법: 2\~4주 실사용 후, 원탭으로 기록한 결제와 다음 달 카드 청구서를 건별로 대조한다. 수치는 2단계에서 확정한다.

## 미결 사항과 다음 단계

이 문서가 확정되면 2단계(요구사항 정의)에서 아래 항목을 정한다.

- [ ] 핵심 플로우: 첫 화면, 금액 입력 방식, 결과 화면 구성, 결제 기록 방식, 위치 감지 실패 시 처리
- [ ] 추천 정책: 동률 처리, 포인트·마일리지 환산, 금액 미입력 시 비교 방법
- [ ] 실적·한도 정책: 기록 방식, 월 기준일, 취소·환불 처리
- [ ] 예외 처리 정책: 실적 제외 항목, 중복 불가, 가족카드 등
- [ ] 성공 기준 수치 확정
- [ ] 수익모델과 출시 여부 판단 시점

별도 준비물: 보유 카드 목록(카드사·상품명·신용/체크). 3단계에서 20장 선정과 C안 테스트에 쓴다.
