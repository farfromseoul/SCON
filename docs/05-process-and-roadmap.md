# 진행 방식과 로드맵

## 원칙

단계마다 산출물을 만들고 → 기획자가 검토·확정하고 → 다음 단계로 넘어간다. 확정되지 않은 단계를 건너뛰어 구현하지 않는다.

## 단계별 산출물

| 단계 | 산출물 | 확정할 것 | 상태 |
| --- | --- | --- | --- |
| 1. 서비스 정의 | 서비스 개요서 | 컨셉, 타깃, 문제 정의, 경쟁 분석 요약, 차별점, MVP 성공 기준 | 초안 완료 (`01-service-overview.md`) |
| 2. 요구사항 정의 | 시나리오·유스케이스, 기능 목록(MVP/v2/이후), 정책서 | 추천 정책, 실적·한도 정책, 예외 처리, 카드 등록 정책, 결제 기록·대조 정책 | 완료 (`06`~`09`) |
| 3. 데이터 기획 | 혜택 데이터 스키마, 업종·브랜드 분류 체계, 지원 카드 목록(첫 20장), 데이터 운영 프로세스 | 혜택 표현 구조, 수집·검수 흐름 | **다음** — 방향 확정 (`04-data-strategy.md`), 브랜드 사전 초안 (`data/`) |
| 4. 화면 기획 | IA, 사용자 플로우, 와이어프레임, 화면 정의서 (사용자 + 관리자) | 화면 구성과 동작 | 시안 초안 (`design/`) |
| 5. 디자인 | 디자인 시스템, 화면 디자인 | 시각 스타일 | — |
| 6. 설계 | 아키텍처, DB 설계, API 명세, 기술 스택 | 구현 구조 | 기술 방향 제안만 |
| 7. 개발 계획 | 마일스톤, 정확도 검증 테스트 케이스 | 개발 순서, 완료 기준 | — |

## 3단계에서 할 것

- 혜택 데이터 스키마 v0 (정책서 06~08의 “3단계 스키마 반영 사항” 포함)
- 기획자 보유 카드 7장으로 스키마 검증 (처음 5장은 직접 구조화)
- 업종 분류 체계 확정, 업종별 대표 금액 표, 브랜드 사전 “기본 결제 경로” 채우기
- 첫 20장 선정
- 정확도 테스트 케이스(기획자가 실제 카드 내역으로 작성)

## 카드 데이터 확대

| 단계 | 장수 | 넘어가는 조건 |
| --- | --- | --- |
| 1단계 · 본인 사용 | 20장 + 내 카드 | 스키마로 20장이 모두 표현되고, 내 카드 계산이 실제 청구서와 맞음 |
| 2단계 · TestFlight (지인) | 50장 | 카드당 검수 시간을 실측해 300장 일정 산정 |
| 3단계 · 출시 준비 | 100장 → 300장 | 요청 대기열 수요 반영, 단종 카드 추가 |

## 배포 계획

1. **기술 검증 (선택, 병행 가능)**: 시안 화면 + 예시 데이터로 빈 앱을 만들어 기기 설치까지 확인. 위치 권한, MapKit vs 카카오 로컬 비교.
2. **본인 사용**: 무료 Apple ID로 Xcode에서 본인 iPhone에 설치. 7일마다 재설치 필요, 일부 기능(푸시, 앱–위젯 데이터 공유 등) 제한 가능성 있음.
3. **지인 테스트**: Apple Developer Program 가입(연 99달러) → TestFlight. 내부 테스터는 심사 없음, 외부 테스터는 베타 심사.
4. **출시 판단**: 정확도·사용 습관 결과와 수익모델 검토 후 결정.

필요 환경: Xcode가 설치된 Mac (iOS 빌드는 macOS에서만 가능).
